# 初始化与接续：P00a / P00b

## 当前窗口讨论

模式一、二先核对是否已有项目，按[进度恢复](进度与恢复.md)接续；新项目逐轮讨论用途、使用者、场景、产物、边界、验收、依赖、模型预算和时限。有材料使用文档拷问组合；已确认事项不重问。首轮真实模式非 Plan 时明确建议开启，正式计划等待真实 Plan 和生成许可。

讨论必须覆盖 P00a、P00b、P01–P11 每个岗位是否需要、数量、职责、平台、模型/档位及原因。包括是否使用网页顾问、反重力/DeepSeek 等外部员工、是否启用 P02、多个 P05 的任务绑定。模式二完整覆盖全部岗位选择，按与用户统一的名单创建；模式一材料与员工精简，但仍采用双 P00。

## 阶段确认

1. 讨论充分，真实 Plan 已开启且获准生成正式计划。计划明确初始化方案、预计员工名单、模型、材料、通知目标与覆盖范围。
2. 用户批准执行且真实退出 Plan，创建或复用 P00a。P00a 请求 `gpt-6.1-sol / high`，实际读取批准计划和角色，写 PRD、复杂任务设计及初始化配置；随可恢复片段保存进度。不能让 Luna 替代主 PRD 编写。
3. 用户确认初版主 PRD 后创建或复用 P00b，请求 `gpt-6-luna / xhigh`。P00b 按已定内容填目录、卡片、总表、窗口清单及项目指引；不得自行补需求、改架构、选模型或编主 PRD。
4. P00b 按获批名单创建/复用普通员工并发送只读报到材料，P11 单独执行获批连接初始化。主 PRD 确认不授权普通员工业务执行。
5. 核对报到和交接后告知用户进入 P01 明确开工。可沿用已批准的有界开工转达：原 human 消息可核验，项目/范围/目标匹配，实际送达接收且 Default；编排器自述不能代替真人授权。分别记原始 thread/turn、来源和接收。

## 创建与报到

先用 list_projects 核对项目 ID，再查项目已有记录和 list_threads；同标题不算匹配。为接收方提供准确工作区、当前技能源码/安装位置、候选身份、角色及任务材料版本，聊天默认 cwd 单记。所有 P 岗位为真实聊天，子代理不得替代。

```js
create_thread({
  prompt,
  target: {type: "project", projectId, environment: {type: "local"}},
  model,
  thinking,
  title
})
```

model/thinking 来自批准名单；P00a 使用 high，P00b 使用 xhigh。创建者将返回的 threadId/hostId 与请求配置登记并补发，clientThreadId 仅表示待完成创建。消息送达、开始、实读报到和完成分别核实；后台实际模型不可见写未知。模型不匹配或工具失败时报告准确错误、待创建/待转交状态，不假称成功或无效参数重试。

普通员工完整读取共用前缀、角色卡、任务卡及必要规则，报告职责理解、路径与版本、缺项和待命状态。P04 此时不写业务执行提示词；P11 按批准设置配置并复验连接。新增业务窗口也先报到再明确派任务。

外部平台提供必要材料正文、完整初始化提示词、模型预算、只读限制与报告接回方式；由用户手动转交，未实发标待转交。外部尚未确认不标整体初始化完成。无外部时内部完成即整体完成；连接失败可明确降级本地可继续范围，不能标网页就绪。

## 交接与正式推进

P00b 核对必要员工实际报到，向 P01 交主 PRD、任务卡、员工身份、模型、授权依据、连接/外部状态及缺项，核验送达接收后结束初始化并移交进度负责人。

P01 获明确开工后只派发当前依赖已满足的一批任务，保存派发记录并结束本轮，不持续等待或追踪。P02 对照新报告查收、更新状态，对依赖解锁、失败、阻塞和待决事件按批准范围唤起 P01。普通进度汇总，不逐条唤醒；同任务卡版本同事件去重。范围变化交用户决定。


正式计划生成前先询问“现在是否生成正式计划”，明确同意或直接要求生成才输出。已获生成许可且范围未变时沿用，不因等待真实 Plan 重问；重新讨论后的完整替代计划重新获准。生成计划须处于真实 Plan；修改文件、建窗和实施须有执行授权且真实退出 Plan。PRD 确认授权获批员工初始化，正式业务另等开工指令；各关口分别记录。
