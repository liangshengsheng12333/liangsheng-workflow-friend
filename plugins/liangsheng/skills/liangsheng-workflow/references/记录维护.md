# 记录组织与维护

## 新项目默认位置

共享记录根目录须核实绝对路径与访问能力。主 PRD 和项目总表保存项目级批准依据与摘要；每个任务只保留一份当前有效任务卡：

```text
工作流/
  PRD.md
  项目总表.md
  任务/
    T01/
      任务卡.md
      提示词/T01-Codex-P05-v1.md
      报告/T01-Codex-P05-R01.md
      报告/T01-反重力-P05-R02.md
```

任务目录按用途分类。提示词文件名含任务号、目标平台、角色和版本；报告名含任务号、实际执行平台、角色和唯一报告编号，时间、模型、任务卡版本及交付版本写正文。平台标识统一为 `Codex`、`反重力`、`DSH`，独立任务没有 P 角色时用“当前窗口”。提示词作者与目标平台分别记录；反重力报告由 Codex 代存时仍标反重力，并注明用户手动转交，不改变执行归属。

代码和正式交付物放在原有合适位置，记录引用它们，不另复制整套代码。远端查询报告可留在既有 `工作流/报告/远端/` 项目级位置。已有项目沿用既有位置；迁移须走 P08 具体文件调整方案，升级插件不迁改历史项目。独立任务只按真实交接、验收需要保存材料，不强制建整套目录。

## 清理批准与负责人

模式一在执行前的简要确认中、模式二在 PRD 中，明确允许清理的工作流记录目录和类别、保留依据及生效时点。用户确认该范围后，符合规则的收尾维护无需逐次审批。缺少确认时只列待清理项，规则外文件另交用户决定。

模式二由 P02 更新记录并执行获批的记录清理；模式一由当前窗口处理。P08 继续负责影响代码或正式文档路径的移动、改名与整理，遵守原批准规则；P02 的清理不包含源代码、用户原始材料、正式交付物、`.git`、凭据、依赖和构建/缓存目录。

## 生效条件与保留内容

对应范围的最终检查和适用审查通过，交付版本匹配且没有未解决问题，才进入清理。待查收、待补证据、待复查、有条件通过且问题未解决、未核实或仍有待交接的材料，不当作可清理旧版。

保留最终有效交付的引用、批准依据、当前任务记录、必要测试与审查证据、恢复信息和已处理报告编号。不固定保留上一套完整版本，不靠新增同样大的备份副本实现省空间。过程报告在执行和验收期间按独立编号保存；审查通过后仅清理已被替代、没有有效引用、不再支撑验收或接续的过程稿、重复副本和旧记录。仍支撑最终结论的旧报告属于必要证据，不删除。

## 收尾步骤

1. P02 根据审查覆盖的任务及最终交付版本更新当前记录、有效成果位置和下一步；独立任务依据用户范围的检查结果维护必要记录。
2. 核对任务卡、总表、批准材料、最终报告、恢复信息及待处理交接引用。已处理报告编号保留在任务卡；清理文件正文不清掉编号或重置任务版本。
3. 列出真正符合已批准类别的冗余项，并解析准确路径，确认均在获批记录目录内；跳过仍被引用、归属不明、其他窗口正在使用或条件不满足的文件。不要递归删除整项任务目录。
4. 清理符合条件的文件，随后核实保留文件可读、有效引用可解析；在当前任务记录简记清理范围与结果，不另建一套历史账本，不更改既有报告结论。
5. 给出下一步指引。只有冗余记录清理时检查文件与引用即可，不新增完整总审；影响代码或正式交付物的调整另走原有 P08/P07/P09 流程。
