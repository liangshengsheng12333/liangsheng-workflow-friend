# 初始化连接与日常咨询

模式二获批启用顾问时在初始化阶段由独立 P11 主动配置连接；模式一按讨论中确认的顾问需求启用。旧项目接续按任务需要和已批准设置处理。普通员工报到不咨询业务问题；正式开工后才执行下文按职责咨询规则。

# 网页顾问

这是凉笙对已安装 Codex with ChatGPT 的接入规则。网页在当前员工职责内分析问题、建议做法或编写代码，Codex 员工核验并落地。项目决策与状态仍由凉笙管理。此文件不是新的 Skill；缺少外部组件时只停用咨询，主驱动和 26 个子技能照常使用。

## 何时使用

| 当前情况 | 动作 |
|---|---|
| 模式一未启用顾问，或独立任务没有明确咨询要求 | 不咨询、不检查或配置连接 |
| 模式一及其他独立任务，用户明确要求咨询 | 可在当前模式咨询，按下述规则验证连接；无需切换模式 |
| P01，没有用户明确要求咨询 | 不咨询；收到其他员工的咨询结果也不自动重复问网页 |
| 详细提示词已明确做法 | 直接执行；遇到具体困难才咨询 |
| 简短任务卡目标与验收明确，实施方法需要斟酌 | 执行前咨询实施建议 |
| 指令虽短，但操作明确 | 直接执行 |
| 目标、范围或验收不明确 | 流程内交 P01 澄清；独立任务直接问用户，不让网页补需求 |
| 难以解释的报错、证据不足以选定局部方案 | 提供已有证据，咨询当前疑问 |

模式二员工可在自身职责与获批设置内按需咨询；模式一已批准网页顾问的员工也按此执行，未启用时须用户明确要求。旧项目接续按明确任务需要及项目已批准设置处理。P02 不做战略规划或代码审查；P04 继续负责复杂提示词，网页不默认重写完整提示词；P09 使用独立审查对话并自行核实关键证据。任务批准不等于用户要求 P01 咨询。

用户将 Sol 执行员切换为 Luna 后，需要较多思考的实现可让网页给具体代码，再由 Luna 核对当前文件、应用改动、衔接和验证。明确小改动直接做；不按模型名称强制每步咨询。不自动改模型或档位，Luna 档位遵守本轮获批配置；用户明确切换覆盖的任务同步批准配置，实际模型另记。网页模型能从当前界面确认则记录，否则写未知，不把用户的模型描述当成实测。

## 接入凉笙专用组件

1. 实际咨询触发后，完整读取本包 `../../codex-with-chatgpt/SKILL.md` 及需要的参考。适配器提供实际 checkout、Node 和状态目录；不读取原独立技能 Locations，不硬编码用户路径。
2. 每次咨询前通过适配器检查当前任务工作区的 status 与 session。只记录必要状态，不输出凭据；旧会话成功不能代替本次检查。只读检测与需要写入的修复分开，不把检查失败直接变成重建。
3. 健康连接复用；首次配置或失效按[连接维护](连接维护.md)自动创建或复用同工作区按获批配置的 P11 专窗。默认自动配置、临时地址，组件缺失仅安装已验证版本。无法核实入口/版本或开窗工具不可用时明确受阻，本地独立部分继续。
4. 原任务收到维护结果后再次检查。仅使用当前环境实际内置浏览器；提供 cua_repl 时遵守首次调用规则及返回文档，使用支持的 DOM API。不假定旧接口存在，不用外部浏览器或 shell HTTP 代替网页操作。
5. 每次发送咨询前，在当前员工顾问对话通过准确连接调用 workspace_info，并读取本轮任务文件验证路径与版本。可在同一请求中要求先核实再分析，指向不符就停止。维护报告不能代替原窗口复验，目录外不可读材料如实报告。

底层升级统一经专门维护验证，日常员工不自动更新。不运行原版 INIT/PLAN/EXECUTED 指挥循环，不覆盖原版session检查点；顾问URL和恢复位置保存到凉笙已有任务记录。朋友使用自己的安装与工作区连接，个人配置不打包。

## 对话、串行与恢复

同一任务/员工/咨询用途可复用对话，保存当前 URL 与进度到已有任务记录的网页顾问栏。P09 对话与执行/方案对话分开。同一任务由不同平台接力时带任务卡版本及实际交付版本，不将原建议用于未核对的新版本。

普通 Chat 可用于顾问，不要求用户创建或绑定 ChatGPT Project；原组件 `session` 的 Project 未就绪不等于连接不可用。按[连接维护](连接维护.md)核实实际本机状态目录，避免沙箱隔离造成重复配置。当前员工仍须在自己使用的对话中实际核实准确工作区和任务文件。

若现有 ChatGPT Project 指令要求网页统筹全项目，不覆盖其指令；在同一内置浏览器页创建不继承该冲突指令的普通 Chat 对话，并选用该工作区已有连接。原版 long-chat 单对话限制在本接入中改为按任务/角色隔离，不重写它的 session URL 或 coding-loop 检查点。不能取得独立且可用的顾问会话时标咨询受阻。

同工作区咨询串行。先确定各咨询窗口都可读写的同一临时锁根目录，优先使用原组件已可写的本机状态目录下 `liangsheng-advisor/`；不能各取沙箱自己的 TEMP。连接维护与咨询共用此锁；移交维护前保存恢复位置并释放当前窗口自己的锁，维护窗口取得锁后才操作网页，不持锁等待对方。开始浏览器操作前，使用本主技能的 `scripts/advisor_lock.py acquire --workspace <绝对路径> --lock-root <共享临时锁目录绝对路径> --owner <任务-角色-唯一窗口标识>`（使用当前可用 Python）。锁仅用于操作互斥，不是项目状态源；同工作区已有持有者时等待或做无依赖工作，不覆盖其页面。完成或明确暂停后用相同参数 `release`；中途超时先找回原页、核实是否已有回复，再继续。释放前将恢复位置记入已有记录。没有可用 Python 或共同可访问的锁根目录时，仅在能确保当前工作区没有其他咨询者的单窗口中咨询，否则留待接续。

页面显示仍在生成时适当间隔读取 DOM，不反复截图、不重复提交。超时不等于问题未发送或代码未应用；恢复时核对当前文件与测试证据。未确定锁持有者已经退出，不删除别人的锁；既有等待不会触发新后台服务或唤醒 P01。

## 咨询指令模板

在可用 Chat 对话中发送下面的必要内容，替换变量；可读材料给准确工作区相对路径和行范围。网页通过连接按需读取，不反复粘贴全文，也不索取秘密文件。控制正文优先精简；原组件的 <1 KB 是目标，当前无法通过连接读取的必要任务说明不得因凑长度而省略。

```text
你是凉笙工作流当前员工的网页顾问。
当前员工：{角色；独立任务写当前执行窗口}；任务：{任务号或当前小任务}；版本：{任务卡/输入/代码版本}。
当前连接：{准确连接名称}；工作区：{核实名称}。
先通过该连接核对 workspace_info 及下面相关文件，指向不符就停止并说明。
目标与完成标准：{已确定内容}。
允许范围：{文件/模块与既有约束}。
具体问题：{一个当前疑问}。
相关材料：{可读的相对路径、必要行范围、差异或已发布执行证据位置}。
已尝试与结果：{简短实际证据，没有则说明未尝试}。
需要的产物：{分析 / 局部方案 / 可应用的代码与位置}。

只为当前员工出谋划策，不指挥 P01、不派员工、不改变范围、接口、依赖、模型、预算或发布决定。
给简短依据、建议、涉及文件、必要代码及验证办法；需要改变已批准事项时明确指出并交本地员工处理。
按真实外部边界处理输入，不增加无依据的兜底、兼容层或未来抽象；不输出完整思维链。
代码由本地员工核对和应用。你的回复、完成声明和建议测试命令不代表测试已运行或项目验收通过。
```

P09 增补：这是独立审查，只读核实指定版本和验收证据，不沿用执行对话的通过结论；不实施修复或新增一轮全项目循环。

## 本地落地与停止条件

先核对建议/代码对应当前文件、公共接口及批准范围，再实施；运行当前任务需要的测试或其他验收，记录实际数量及证据，零测试不能冒充通过。出现具体错误时可携证据继续同一咨询，但咨询不重置两轮无进展计数。正常红绿测试、有新证据的排查不计为无进展。

网页连接首次未配置或失效时先执行连接维护；自动恢复后仍无连接、需登录/验证码、无可用回答或指向不符时说明原因：有依据能完成的继续，依赖咨询的部分标受阻。需用户参与时一次给一个具体动作，不要求用户理解内部组件术语，不擅自换付费服务。

对外接口、跨任务依赖、范围、模型、预算或专门授权变化时，流程内交 P01/用户，独立任务交用户。P01 收取员工核实后的结论和证据，不自动再咨询网页。

## 记录与反馈

沿用任务卡和执行报告的网页顾问栏；独立小任务无记录需要时在交付中说明即可。只记用途、关键建议、采用情况、本地核验与恢复入口，不保存每轮聊天全文。使用原组件的现有执行证据能力时按所需范围记录，不向其 session 写凉笙任务状态。

网页提供代码、Codex 应用时，实际执行平台仍为 Codex。反重力与 DSH 的咨询请求仍由用户转交到 Codex，结果准备成可复制材料，未转交不声称外部已收到。不新增后台扫描。

反馈可写“这次使用网页顾问分析了加载方案，由 Codex 应用并通过 3 项测试”。仅打开页面或读取 Skill 不算已采用；建议无效或受阻如实写。可确认的模型与用量如实记录，无可比较数据不声称节省百分比。

连接维护窗口默认申请配置所需的提升权限；创建工具不能设置整窗权限时，配置命令按需要申请 require_escalated，以环境实际审核结果为准，不假称整窗权限已改变。
