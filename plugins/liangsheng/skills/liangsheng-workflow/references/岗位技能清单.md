# 岗位技能清单 v2.1

本 JSON 清单是驱动选择的唯一岗位许可源，Markdown 是可读说明。角色卡记录 canonical 岗位；P05-T01 等任务窗口仍绑定 P05，不从标题推测。

全岗位共有 `handoff`（交接与恢复）和 `wait-what`（通俗重述）。文档拷问组合明确包含 `grill-with-docs`、`grilling`、`domain-modeling`，三者共同许可。

## DISCUSS｜当前讨论窗口

确定用途、范围、验收和本轮员工。

- `grill-with-docs`（文档拷问）：结合材料逐轮讨论，实际组合 grilling 与 domain-modeling，澄清决定并记录已确定术语。
- `grilling`（决策拷问）：用户希望针对一个具体决定逐轮追问假设、取舍和依赖时使用；整体构想按材料情况选构想或材料拷问。
- `domain-modeling`（领域梳理）：业务词汇含糊、同词异义或业务边界不清时，结合材料澄清术语、例子与关系，复用已有词汇表。
- `grill-me`（构想拷问）：用户只有初步构想、希望逐轮追问以澄清目标和范围，且没有现成项目材料时使用；有材料用材料拷问。
- `ask-matt`（路线指引）：用户不知从哪里入手、需要判断工作路线时，依据目标推荐最短有用的技能顺序；复杂未知依赖用路径探明。
- `wayfinder`（路径探明）：复杂多阶段目标含有尚不清楚的关键决策、未知条件和依赖，用户希望梳理先后顺序时，建立决策图并逐步消除未知。
- `research`（事实查证）：用户需查证官方文档、外部事实或技术依据以支持决定时，核对一手来源并交付带链接的结论；纯解释不扩大研究。
- `prototype`（快速原型）：用户想先做可操作演示来比较界面、交互或状态逻辑时，制作标为试验的最小可运行产物。

## 许可与组合

驱动选技能、技能内部建议另一个技能、临时代理使用技能，都核对本清单。超清单交对应岗位；改变清单须用户确认。文档拷问只澄清当前任务，不重启项目。研究/设计结论改变需求、接口或跨任务依赖时交 P01 与用户。

普通员工初始化只读报到。网页咨询仅在项目已批准且符合本岗位职责时条件启用；P01 还须用户明确要求，连接/恢复操作归 P11。临时代理每批先询问并等待同意，继承岗位、任务和读写限制。

CURRENT 用于没有 P 身份的独立请求；P 员工不得改用 CURRENT 绕开岗位清单。teach 与 improve-codebase-architecture 默认是独立教学/巡检入口。
