# 代码简洁约定

适用于新增代码和当前任务直接涉及的修改。无关旧代码的问题只记录建议，不顺手扩大重构范围。以真实输入、支持版本、调用方和已确认业务要求为依据，优先直接实现。

- 在接收外部输入、文件内容或第三方响应的适当边界校验；内部已经建立的契约不在每层重复检查。
- 内部契约被违反时保留清楚、可定位的失败信息。避免吞异常后返回空结果、默认值或假成功。
- 重试、降级、默认值要对应真实失败场景或明确业务要求，并符合操作语义；不为假想问题增加多层备用路径。例如非幂等操作不能盲目重试。
- 兼容层要有已支持版本、真实调用方或明确迁移需求，不预先兼容不存在的旧格式或未来接口。
- 在当前范围内采用直接实现，不为未来可能的需求增设抽象层或兜底框架。

这不禁止 `try/catch`、判空、重试或兼容代码。判断它保护的真实条件和失败后的结果，保留必要的故障处理；常规实现取舍无需逐项审批。

规划时仅在确有需要时明确支持版本、输入边界和故障行为，不笼统要求“全面兜底”。测试验证这些实际行为；审查在既有总审中核对无依据的兜底、吞错和兼容分支，不新增完整审查。

P04 给 Codex、Antigravity、DSH 编写涉及代码的提示词时，加入本约定。能读插件的窗口给准确文件位置；外部窗口读不到时附上述适用范围、五条规则和必要故障处理的说明正文，不能只附不可访问的路径。

## v2.1 审查位置
