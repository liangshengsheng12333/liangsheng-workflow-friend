# 动态驱动：按岗位选技能

## 每轮步骤

1. 核对项目、当前真实模式、阶段、任务卡版本、允许操作与窗口身份。首次、上下文压缩后或不确定时读主技能、进度、当前任务及必要资料；之后复用已加载规则，变化处才补读。原聊天或产物不能访问时标缺口。
2. 从角色卡取得 canonical 岗位，不从标题猜。读取[岗位技能清单](岗位技能清单.md)；路由建议、组合和代理均先过滤清单。独立任务用 CURRENT；P 员工不能改用 CURRENT 绕开岗位限制。
3. 根据下表选择最有用的技能。可用 Python 时运行 `scripts/check_skill.py --role P05 --skill implement --stage work`（相对主驱动目录）；条件咨询补 `--advisor-enabled`。退出码非零则停止该技能，按输出转交或补前置条件。没有 Python 时按同一 JSON 清单人工核对并说明；这是驱动检查，不宣称平台已屏蔽工具权限。
4. 实际读取本包 SKILL.md 和必要参考，执行方法；有材料的设计分歧由主驱动进入文档拷问组合，组合实际执行两个依赖。上游推荐清单外技能时交对应岗位，不借嵌套调用绕过清单。
5. 完成片段、红转绿、故障、设计分歧、研究或原型返回、审查反馈时重新检查适用技能；核对产物和下一步。恢复索引及时更新，详细调用证据留任务报告，不重抄全部正文。

## 触发与产物

| 事件 | 方法与最低产物 |
|---|---|
| 材料/需求/设计歧义 | 文档拷问组合；读材料、当轮前沿与建议、等待答复、重算前沿；确定术语即时记词汇表，Plan 中先在对话保存 |
| 无材料构想 | grill-me + grilling；逐轮问题、回答与明确结论 |
| 缺外部事实 | research；一手来源、日期、事实/推断与可读研究文件 |
| 必须体验才可决定 | prototype；可运行试验、原始文件、问题及判定指针 |
| 明确实现任务 | implement；相关改动、适用 tdd 红绿、实际验证与任务代码自查 |
| 真实故障 | diagnosing-bugs；先有失败反馈再假设、同一路径验证、未复现的缺口 |
| 模块接口取舍 | codebase-design；真实调用者、接缝、可行方案与取舍；范围变化交用户 |
| 完成代码任务/指定审查 | code-review；规范和需求分别结论、差异与版本、实际审查方式 |
| 复杂未知依赖 | wayfinder；地图、前沿、认领及答案指针，保留未明确/范围外区分 |
| 阶段/窗口/平台边界 | handoff；版本、成果、未决项、恢复位置和下一动作 |

其余技能按[调用说明](子技能调用说明.md)匹配，仍先检查岗位许可。无增益的简单解释、查收、更新状态和固定建窗无需强行凑技能数。借鉴上游的触发、加载正文、检查产物与事件重判机制，决策等待用户，批准范围内常规细节由员工处理。

## 岗位、代理和派发

初始化普通员工只读报到；选技能不提前开工。P00a/P00b、P11 的初始化职责按批准方案执行。P01 只处理本次事件对应的一批派发，登记状态后结束，不用 wait_threads 持续跟踪执行；P02 汇总普通进度，只有依赖解锁、失败、阻塞或待决时按获批通知范围唤起 P01。同项目同任务卡版本同事件只处理一次。

每次启动临时子代理前，说明目的、数量、输入与范围并等用户同意。许可只覆盖明确本批；代理继承岗位清单和任务限制。未获准可顺序自行处理可验证内容，自查不冒充隔离审查。P09 是真实独立员工，最终审查独立性与任务自查分开记录。

自动技能选择不改变模型、预算、接口、跨任务依赖、对外写入或发布权限。两轮同法无新证据停止并交接，正常有进展的红绿和排查不计入。网页咨询按获批项目设置，P01 仅用户明确要求时咨询；配置和恢复交 P11，不操作其他工作区。
