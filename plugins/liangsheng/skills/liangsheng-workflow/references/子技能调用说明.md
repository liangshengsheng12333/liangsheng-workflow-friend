# 26 个子技能：名称、用途与自然表达

版本 2.1.0。按意图读取正文并核验产物；独立小任务不强制初始化，模式一、二遵守初始化与接续，统一进度恢复，按岗位清单驱动。所有 P 岗位是独立聊天。

| 英文名 | 中文名 | 功能 | 自然表达示例 |
|---|---|---|---|
| `ask-matt` | 路线指引 | 用户不知从哪里入手、需要判断工作路线时，依据目标推荐最短有用的技能顺序；复杂未知依赖用路径探明。 | 我有点不知道该从哪里下手：现在既有几个新点子又有一个报错。请帮我判断先做哪类工作、建议顺序即可，别替我开发。 |
| `code-review` | 代码审查 | 用户要检查指定代码改动、工作区差异或分支质量时，核对规范与需求；调查正在发生的故障用 diagnosing-bugs。 | 请检查当前工作区相对最近提交的改动，看看是否符合 notes.md 中的要求，给出问题和依据。不要修代码。 |
| `codebase-design` | 模块设计 | 用户要比较模块职责、接口或测试接缝、决定如何划分代码时，评估不同设计及调用成本；不自行实施扩大范围的重构。 | 请结合现有代码比较两个方案：把订单计价留在一个函数，还是拆为校验、计价两个模块。重点看职责、调用负担和怎么验证，先给设计建议。 |
| `diagnosing-bugs` | 缺陷诊断 | 用户报告报错、结果异常、偶现失败或性能退化，要求找原因和修复时，建立复现并验证根因；一般改动审查用 code-review。 | 这段折扣计算不对：价格 0.15，打七折应该得到 0.11，实际却是 0.10。请找原因并修好，用测试证明。 |
| `domain-modeling` | 领域梳理 | 业务词汇含糊、同词异义或业务边界不清时，结合材料澄清术语、例子与关系，复用已有词汇表。 | notes.md 里‘账户’同时指登录身份、店铺余额和客户档案，大家经常搞混。请厘清这些词各指什么，给出共同用语和例子。 |
| `grill-me` | 构想拷问 | 用户只有初步构想、希望逐轮追问以澄清目标和范围，且没有现成项目材料时使用；有材料用材料拷问。 | 我想做一个帮助老人记住吃药的点子，目前还没有项目资料。请一轮一轮问我，让目标和一期范围慢慢清楚，先别写代码。 |
| `grill-with-docs` | 文档拷问 | 结合材料逐轮讨论，实际组合 grilling 与 domain-modeling，澄清决定并记录已确定术语。 | 结合这个仓库和 notes.md 问我几个关键问题，帮我把新增订单导入这件事想清楚。先讨论，不开发。 |
| `grilling` | 决策拷问 | 用户希望针对一个具体决定逐轮追问假设、取舍和依赖时使用；整体构想按材料情况选构想或材料拷问。 | 我现在只想决定退款是否要允许部分金额。这一条决定牵涉哪些前提和取舍？请逐轮追问我，每轮等我回答。 |
| `handoff` | 任务交接 | 用户要换窗口、换人、换平台或中断后续接时，整理目标、已做工作、版本、证据和下一步，供接手者继续。 | 我要换一个聊天继续这项工作，请把现有目标、做过什么、代码版本、剩余问题和下一步整理成接手说明，保存到 transfer.md，不用发给任何人。 |
| `implement` | 功能实现 | 按明确规格或任务实现，执行适用测试并做任务代码审查；真实故障先诊断。 | 给 app.py 加一个 total(items) 函数，求整数列表总和，空列表为 0。完成实现并验证这个小改动。 |
| `improve-codebase-architecture` | 架构巡检 | 用户想找结构问题、维护痛点或值得重构的部分时，基于近期改动与真实摩擦提出候选；与直接实现指定功能区分。 | 看一下这个仓库有哪些结构让后续维护费劲，找值得改的部分，给有代码依据的候选建议，先不重构。 |
| `prototype` | 快速原型 | 用户想先做可操作演示来比较界面、交互或状态逻辑时，制作标为试验的最小可运行产物。 | 先做一个能操作的订单状态演示让我体验：待付款→已付款→退款完成。用单个 HTML 文件显示每次操作后的状态，标明是试验品。 |
| `research` | 事实查证 | 用户需查证官方文档、外部事实或技术依据以支持决定时，核对一手来源并交付带链接的结论；纯解释不扩大研究。 | 请查证 Python 官方资料里 Decimal.quantize 的 ROUND_HALF_UP 如何处理 0.105，交付带一手来源链接的简短结论，保存到 findings.md。 |
| `resolving-merge-conflicts` | 冲突解决 | 用户要解决 Git 合并或变基冲突且仓库确有未解决冲突时，核对双方意图并验证；不自动推送或合并主分支。 | 这个仓库正在合并，app.py 有冲突。请结合两边提交意图处理冲突并验证。不完成合并提交，不推送。 |
| `setup-matt-pocock-skills` | 规范接入 | 用户要为仓库补齐代理协作所需的记录、术语或指引入口时，检查缺项并复用已有状态源；不启动完整立项。 | 请为这个仓库补齐 AI 代理工作需要的任务记录入口、业务词汇位置和指引，但保留 todo.md 作为唯一任务来源，别建第二套。把接入结论保存到 agent-setup.md。 |
| `tdd` | 测试驱动 | 在适用公共接缝逐片执行失败测试、最小实现和通过验证；解释请求只讲方法。 | 先写一个失败测试，再实现 app.py 的 total(items) 小功能：整数列表相加，空列表返回 0。一次验证一个行为，保留失败到通过的证据。 |
| `teach` | 系统教学 | 用户想系统学习一个主题、安排练习并获得反馈时，按基础和目标逐步教学；单句解释不启动课程。 | 我懂 Python 函数但不会写自动化验证，请带我系统学这件事，安排三次短课，每次有练习和反馈方式，先给第一课。 |
| `to-questionnaire` | 调研提纲 | 用户要向他人收集信息、准备访谈或回填问题时，生成有重点的提问稿；不自动发送。 | 我们要向仓库保管员了解收货和盘点流程。请写一份让他回填的问题清单，重点收集异常流程和数据量，不要发送。 |
| `to-spec` | 规格成稿 | 用户希望把已讨论清楚的需求整理成规格、产品文档或验收标准时，综合现有决定成稿；独立小需求不强制全套字段。 | 需求已确定：本地导入订单 CSV，只支持 UTF-8 的 id,amount 两列，坏行需报行号，不写数据库。这次只把需求整理成可验收规格，保存到 requirements.md。 |
| `to-tickets` | 任务拆分 | 用户要把已明确的需求、方案或规格拆为可独立验收的小任务并排依赖时，生成纵向任务清单；未经整理的原始反馈用 triage。 | notes.md 中的订单 CSV 导入范围已经确定了。请拆为几个能独立验收的开发小任务，写清各自范围、验收标准和先后依赖，保存到 steps.md，不派发窗口。 |
| `triage` | 事项分诊 | 用户提供零散反馈、缺陷或需求，希望分类、去重、核实和排优先级时，形成有证据的待办；明确需求的执行拆分用 to-tickets。 | 把这些零散反馈分类、去重、核实哪些要进一步查：折扣尾数不对；导出按钮太难找；折扣 0.15 七折得到 0.10；想支持十年前的未知文件格式。先给有依据的待办建议。 |
| `wait-what` | 通俗重述 | 用户表示没听懂、术语太多或想把刚才的话说简单时，用短句和熟悉例子重述；不自动展开课程。 | 刚才那句‘通过公共接缝建立可证伪的反馈环以提升局部性’我没听懂。请用简单短句和折扣计算例子重新说。 |
| `wayfinder` | 路径探明 | 复杂多阶段目标含有尚不清楚的关键决策、未知条件和依赖，用户希望梳理先后顺序时，建立决策图并逐步消除未知。 | 我要把线下门店系统搬到线上，支付、库存数据来源、权限归属都没定，而且决定相互依赖。请先画清未知问题和前后关系，找当前最先能决定的点，不开始开发。 |
| `wizard` | 步骤向导 | 用户需要亲自登录、授权、输入凭据或操作外部系统时，提供逐步指引；不索取秘密或声称代为操作。 | 我要自己给一个仓库配置托管平台的访问授权，必须在网页上登录和授权。请给我一步一步的人工操作指引，不读取我的密码或令牌，也别替我执行。 |
| `writing-for-agents` | 代理指令 | 用户要编写或改进 AI 代理指令、AGENTS.md、角色提示词或技能正文时，明确触发、输入输出与完成条件。 | 请改进 AGENTS.md，让接手的 AI 明确在哪读任务、允许改哪些文件、怎么判断完成。只改这份代理指令，保持已有任务入口，不开发功能。 |
| `codex-with-chatgpt` | 凉笙 ChatGPT 顾问 | 自动连接、恢复、当前任务咨询与断开；本地负责执行及验收 | 连接 ChatGPT；请网页顾问分析当前任务 |

## 计划生成与改版测试

正式计划生成前先询问“现在是否生成正式计划”，明确同意或直接要求生成才输出。已获生成许可且范围未变时沿用，不因等待真实 Plan 重问；重新讨论后的完整替代计划重新获准。生成计划须处于真实 Plan；修改文件、建窗和实施须有执行授权且真实退出 Plan。PRD 确认授权获批员工初始化，正式业务另等开工指令；各关口分别记录。

日常模型以本轮批准配置为准：P00a 请求 gpt-6.1-sol / high，P00b 请求 gpt-6-luna / xhigh；其余岗位在讨论时确认。配置不可用或不匹配时报告，不静默降级。请求配置与可核实实际配置分开记录，后台不可见写未知。改版测试配置仅见维护验收资料。
