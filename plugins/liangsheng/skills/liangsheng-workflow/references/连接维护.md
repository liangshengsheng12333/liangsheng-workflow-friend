# ChatGPT 连接维护

P11 是独立聊天窗口。模式二讨论先确认顾问设置，获批启用时初始化主动检查、配置或恢复本项目连接；模式一拷问时确认需要网页顾问才启用；旧项目接续与独立任务按明确任务需要和已批准设置处理。P01 仅在用户明确要求时咨询。独立连接请求直接使用本包 `../../codex-with-chatgpt/SKILL.md`。

## 默认与专用窗口

默认自动配置与临时地址，常规安装、依赖和配置已有任务授权时连续完成；已有用户明确选择仍按其选择。必要登录、验证码、2FA、本人授权及付费才交用户一次一个具体动作。系统权限按实际审核申请，不声称已设置整窗权限。

P11 或当前咨询窗口先通过新子技能的适配器检查准确工作区与实际状态目录。健康连接直接复用，普通 Chat 能读取当前连接即可；Project 未绑定不等于失败。首次配置或需要恢复时，按准确工作区路径查找专用维护聊天，最多一个正在配置的窗口，不仅凭标题判匹配。

Codex 桌面工具可用时先 `list_projects` 找到匹配项目，再在用户授权范围内 `create_thread` 创建本地维护聊天，标题“P11｜连接维护”，使用本轮获批模型与档位（建议 `gpt-6-luna` / `high`）；接续用 `send_message_to_thread`。当前创建工具没有整窗权限字段，配置命令需要时申请 `require_escalated`。模型或项目不匹配、工具不可用时给准确可复制任务包，不选择其他项目，不假称开窗。

保存准确 threadId/hostId 和结果位置；clientThreadId 不可用于需 threadId 的工具。使用 `wait_threads` 与游标等待结果，当前窗口继续独立工作；用户动作等待不会触发另一个窗口。

## 维护实施与互斥

维护窗口只完整读取本包 `../../codex-with-chatgpt/SKILL.md` 及其实际需要的配置/恢复参考，不读取已撤出的原独立技能。组件由适配器定位，缺失时安装锁定提交；运行前核实版本和本机状态目录，不在日常任务更新底层。

检查与维护显式使用同一实际状态目录，避免 Windows 沙箱重定向 LOCALAPPDATA 导致误判。路径/权限问题先处理，不能靠反复创建连接掩盖。只操作当前工作区连接，健康连接不重启；不写原版 session 的 Project、URL或 coding-loop 检查点。

与[网页顾问](网页顾问.md)共用 `scripts/advisor_lock.py` 和实际状态目录下 `liangsheng-advisor/` 锁。移交维护前保存恢复位置并释放自己持有的锁；维护操作时取得锁，不持锁等待另一个窗口。只用当前环境内置浏览器 API，Windows 后台辅助进程隐藏启动。

按新技能实际诊断和恢复步骤执行。加载、生成、等待登录不算失败；明确故障完成两轮无新证据/进展后停止同法重试，报告已做动作和恢复入口。不强制切手工配置；仅代理不能完成的用户动作交用户。

## 结果与复验

报告仅保存工作区、请求及可核实模型、threadId/hostId、实际配置/恢复动作、状态、连接名称、恢复入口、网页工作区/文件验证及阻塞。配对码、令牌和凭据不入报告。

原任务窗口收到结果后重新检查连接，并在自己的顾问对话调用 `workspace_info`、读取当前任务文件核实路径与版本。维护窗口的成功不能代替复验。失败时有依据的本地工作继续，依赖网页部分标受阻，咨询不重置两轮无进展计数。

## 可复制维护任务包

```text
你是当前工作区的凉笙 ChatGPT 连接维护窗口，使用本轮获批的模型与档位（未另定时先确认 GPT-6 Luna 高档建议）。
工作区：{准确绝对路径}；结果位置：{已有任务报告位置}。
读取凉笙插件的 codex-with-chatgpt/SKILL.md 及配置/恢复参考，用专用适配器处理当前工作区。
默认自动配置、临时地址；必要底层安装使用锁定提交，不更新底层、不读取或重装原独立技能。
按需要申请实际权限；必要登录、验证码及本人授权交用户完成一个动作。
只处理连接，不修改项目代码；不启动原版指挥循环、不写原版session任务或Project状态。
与原窗口使用同一实际状态目录和咨询锁。健康连接复用；完成后验证workspace_info和指定任务文件。
报告真实动作、验证、恢复入口和未完成项；不保存凭据。两轮无进展则交接，不无限重试。
```

替换维护窗口时保存旧新 threadId 与原因；初始化失败允许降级报告“网页顾问未就绪”，列受阻能力和恢复入口，绝不标连接成功。
