# 进度与恢复

## 极简文件与状态源

项目默认 `工作流/进度.md`，已有项目可在原记录根采用同一短文件，保留原 PRD/任务卡/报告位置。它只作恢复索引；任务事实以实际产物、任务卡、报告和可信批准记录核对。顶部当前状态，底部最多三条关键变化，不存聊天全文或凭据。

```markdown
# 项目进度
项目编号/名称：
准确工作区/记录根：
驱动版本/岗位清单版本：2.1.0
当前阶段/真实模式/更新时间（含时区）：
更新负责人/已移交记录：
已完成：
当前工作及有效产物/版本：
窗口清单位置（含 threadId/hostId、岗位、模型和报到）：
已确认事项及可信来源位置：
待确认/阻塞：
下一动作/负责人/前置条件：
最近变化：最多三条，一条一句
```

详细内容只保存一次并链接。PRD、员工配置、阶段确认、任务卡与报告仍用现有总表和任务记录。更新时间来自本轮真实时钟，不捏造进度。

## 更新时点与负责人

批准执行并退出 Plan 后，创建 P00a 前由创建者先记录创建意图；收到工具回执及时填窗口清单和进度，不等额度耗尽才写。P00a 完成 PRD 小段、保存草稿、提出待确认事项后更新；P00b 每完成记录、建窗、报到、连接或交接小步更新。正式工作按可恢复片段保存任务记录。

项目进度只由一个负责人更新：创建者 → P00a → P00b → P02。精简项目未启用 P02 时明确由当前负责窗口维护。移交写明接收者和依据；其他员工更新自身任务记录及通知，不同时覆盖项目进度。P02 收到新报告核对后汇总，旧报告不覆盖新版本。

## 恢复流程

1. 核对准确工作区和项目身份，读进度、当前主驱动版本、窗口清单及本次必要任务材料，先报告当前断点与下一步。不同项目同名目录、同标题不能证明身份。
2. 对进度晚于或早于产物的情况，核对真实文件、卡片版本和工具回执，补齐可证实变化；记录没有证据的声明为待核实，不猜已完成。历史尝试计数和待确认事项保留。
3. 用 list_threads/read_thread/wait_threads 核对准确 threadId/hostId 和项目，复用可接续且模型、职责匹配的窗口；缺窗只按原批准名单补缺失岗位。未拿到真实 threadId 的 clientThreadId 单独记，先查创建状态，不直接重复创建。
4. 续做原范围内已授权且阶段前提满足的工作。PRD 草稿未完只续写；已建窗未报到只补报到；初始化完未开工仍待命；已开工任务从自身任务记录继续。不把恢复当作新项目。
5. 无进度的旧项目先找已有材料和任务，不强制重建整套 PRD 或员工。有足够明确的本次独立授权就推进，否则只讨论实际缺口。旧 P00 核对当前职责和模型后关联到 P00a/P00b；不能仅改标题就假称配置正确。

## Plan 与跨会话

Plan 内不写项目进度、词汇表、ADR 或建窗。读取当前聊天及可访问原聊天恢复已确认决定，在对话中交当前摘要，退出 Plan 后及时落盘。新窗口通过记录中的真实聊天身份读原聊天；身份或内容不可访问且文件未保存时，说明具体缺口并只补问缺失内容，不能承诺凭空恢复。

P00b 在获批初始化范围内给项目已有 AGENTS.md 添加一条指针，保留周围内容；无文件且批准方案覆盖时建立：

> 此项目采用凉笙。`工作流/进度.md` 存在时，先读进度及其中的有效角色/任务位置，加载当前安装包的凉笙主驱动；按本窗口 canonical 岗位清单继续，不重新初始化。插件路径未知时通过当前技能目录核实，不硬编码其他电脑路径。

只有本项目适用。用户取消或更换任务时更新状态，不因记录存在继续被撤销的工作。
