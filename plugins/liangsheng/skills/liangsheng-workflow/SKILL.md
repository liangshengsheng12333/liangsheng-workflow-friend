# 凉笙工作流 v2.1

先实际读取本正文、[动态驱动](references/动态驱动.md)及当前项目必要材料。用户确认前期方案后自动初始化真实员工聊天；正式开工后每个窗口按自己的岗位清单选择技能。临时子代理每批启动前先询问用户，不能替代员工窗口。

## 项目入口与统一恢复

收到启动或继续请求，先核对准确项目工作区，再读取存在的进度与必要旧记录，识别新项目、同一项目中断、尚未接入的旧项目。采用[进度与恢复](references/进度与恢复.md)，已完成不重做，已建窗不重复建，沿用可信批准记录；先简述断点，再续做原范围内已授权工作。Plan 或等待阶段确认时停在相应关口。

| 请求 | 行为 |
|---|---|
| 小声讨论、小笙讨论、开启小项目、模式一/1启动 | 模式一；先判断是否接续，精简材料和员工，仍采用 P00a/P00b 分工 |
| 一键省流、一键笙流、模式二/2启动、开始建立个人工作流 | 模式二；先判断是否接续，讨论全部岗位、模型、数量及外部员工，再按确认名单初始化 |
| 继续项目、恢复进度、继续 P00、加载凉笙主驱动 | 从实际阶段接续；未接入旧项目先读取材料，为当前请求建立必要记录，不默认整套初始化 |
| 模式三/3启动 | 旧口令兼容入口，转统一接续；不再存在独立模式三流程 |

引用、咨询或编辑口令不启动项目。模式一、二新项目首轮若真实模式不是 Plan，明确建议用户开启 Plan；可先读取与讨论，正式计划必须满足真实 Plan 和生成许可。无法核实时标未知。


## 阶段与窗口

按[初始化与接续](references/初始化与接续.md)完成：当前窗口讨论与正式计划 → 批准执行并退出 Plan → P00a 写初版 PRD → 用户确认 PRD → P00b 建记录、创建或复用员工并收只读报到 → 交接 P01 → 明确开工 → 按依赖批次派发。

P00a 请求 `gpt-6.1-sol / high`，P00b 请求 `gpt-6-luna / xhigh`。其他员工及外部平台的配置在本项目讨论时确认。实际配置不匹配时报告，不自动用 Luna 编写主 PRD。P01 每次派发结束就结束本轮；P02 按已授权事件通知再唤起 P01。窗口创建、消息送达、开始和完成分别核验。

## 每个窗口的技能驱动

读取[岗位技能清单](references/岗位技能清单.md)和本窗口卡片，按[动态驱动](references/动态驱动.md)核对阶段、任务和岗位许可。选中后实际读取技能和必要资料，执行并核对产物；组合内部和临时代理也执行同一检查。清单外工作转交对应岗位，不接管 PRD、需求或其他员工任务。简单说明与常规状态维护可直接完成。

文档拷问组合是 grill-with-docs + grilling + domain-modeling；有材料的讨论优先使用组合，只澄清当前任务。任务完成后执行适用审查，最终整合版本由 P09 独立总审；每次需要临时调查或审查代理都先询问用户。

正式计划生成前先询问“现在是否生成正式计划”，明确同意或直接要求生成才输出。已获生成许可且范围未变时沿用，不因等待真实 Plan 重问；重新讨论后的完整替代计划重新获准。生成计划须处于真实 Plan；修改文件、建窗和实施须有执行授权且真实退出 Plan。PRD 确认授权获批员工初始化，正式业务另等开工指令；各关口分别记录。

日常模型以本轮批准配置为准：P00a 请求 gpt-6.1-sol / high，P00b 请求 gpt-6-luna / xhigh；其余岗位在讨论时确认。配置不可用或不匹配时报告，不静默降级。请求配置与可核实实际配置分开记录，后台不可见写未知。改版测试配置仅见维护验收资料。
