# 连接配置与恢复

## 本机探测

模式二初始化由 P11 主动进入；模式一按已确认顾问设置进入，其他场景仅在连接请求或获批咨询需求触发时操作。下列 `<adapter>` 是本技能 `scripts/c2c-adapter.mjs` 的实际绝对路径；Node 使用当前可用且 >=20 的实际入口。所有工作区参数都指任务工作区，不是底层仓库。

```text
node <adapter> resolve --json
node <adapter> init --component <底层实际checkout> --state-dir <实际状态目录>
node <adapter> bootstrap
node <adapter> run --workspace <工作区绝对路径> -- status --json
```

`resolve` 只读，返回 `componentRoot`/`checkout`、`node`、`stateDir`、`lockRoot`、`configFile` 与固定提交。已有配置优先；首次发现 `LIANGSHENG_C2C_ROOT`、管理组件目录或用户 home 下 checkout，全部核对来源、提交、跟踪文件无改动及已构建入口。不读原技能。自定义位置用 `init --component`，迁移后旧路径失效就重新探测并 init；不原样使用旧电脑配置。配置默认存系统用户配置目录的 `liangsheng/c2c/config.json`，可用 `LIANGSHENG_C2C_CONFIG` 或 `--config` 指定插件外位置。

状态目录与上游一致：非空 `C2C_STATE_DIR`；否则 Windows 为 `LOCALAPPDATA/codex-with-chatgpt`，macOS 为 `~/Library/Application Support/codex-with-chatgpt`，Linux 为 `XDG_STATE_HOME/codex-with-chatgpt` 或 `~/.local/state/codex-with-chatgpt`。已配置时 wrapper 每次显式传 `C2C_STATE_DIR`，防止不同窗口误用沙箱目录。核实实际可写根，不猜测用户名或改用各窗口 TEMP。需要权限时按环境申请命令级提升，实际审批失败要报告，不假称整窗权限已改变。

新电脑 `bootstrap` 只克隆锁定来源与提交，安装锁定 pnpm、使用 frozen lockfile 构建 C2C，不安装上游技能、不更新到 latest，不改变现有 checkout。Node/npm/git 由实际环境提供；缺少者由维护窗口用平台安装渠道补齐后继续。缺少 cloudflared 时维护窗口用平台渠道安装（Windows `winget install --id Cloudflare.cloudflared --exact --silent --accept-package-agreements --accept-source-agreements`，macOS `brew install cloudflared`，Linux 按已配置包管理器），核实成功再继续；只能本人安装/授权时明确给出一个必要动作。底层 pin、许可与构建来源见 [upstream-lock.json](upstream-lock.json)。

## 共享锁与自动配置

维护窗口按主驱动的模型和岗位规则创建/复用。使用实际可用 Python 执行主技能 `../liangsheng-workflow/scripts/advisor_lock.py`，`lockRoot` 取上一步返回值，`owner` 为任务和窗口唯一标识。

```text
python <主技能>/scripts/advisor_lock.py acquire --workspace <绝对路径> --lock-root <返回lockRoot> --owner <唯一owner>
node <adapter> run --workspace <绝对路径> --owner <唯一owner> -- prefs set --setup-mode auto --json
node <adapter> run --workspace <绝对路径> --owner <唯一owner> -- tunnel choose --mode quick --json
node <adapter> run --workspace <绝对路径> --owner <唯一owner> -- setup --json
python <主技能>/scripts/advisor_lock.py release --workspace <绝对路径> --lock-root <返回lockRoot> --owner <唯一owner>
```

锁是互斥，不是项目状态。被占用则等待或继续无依赖工作；不删除未知持有者的锁。必须覆盖浏览器配置/咨询全程，不能只锁一个 CLI 命令。wrapper 验证非只读操作的 owner，禁止上游 update/安装流程和项目检查点。`prefs set --developer-mode` 只能在页面实际确认开启后写，不能仅因设为 auto 就宣称页面已配置。

先 `status`。桥、隧道、授权和浏览器实际验证健康时直接复用，不重复 `setup`/生成配对码或切换隧道。未授权/首次才采用上述自动配置顺序；默认 quick，但不为改偏好而打断健康的旧连接。取得 `setup` 的准确 `mcpUrl`、连接名和短时配对码后读[浏览器与咨询](浏览器与咨询.md)完成网页操作，配对码只用于授权页，不落报告。

## 恢复与失败交接

先记录本次故障、当前 URL、必要任务版本和恢复位置。状态 `running:null`/unknown 不视为停止，不盲目重启。维护窗口在锁内用 `doctor --no-fix --json`诊断；确认可修复时用 `doctor --json`，检查 report 与 chatgptRepair，不只看退出码。无公网的首次连接仍须 setup，doctor 的“本地模式正常”不代表网页可用。

```text
node <adapter> run --workspace <绝对路径> --owner <owner> -- doctor --no-fix --json
node <adapter> run --workspace <绝对路径> --owner <owner> -- doctor --json
node <adapter> run --workspace <绝对路径> --owner <owner> -- pair --json
```

临时地址更换时只更新对应连接；旧地址不能靠 Reconnect 恢复。页面不允许改地址时，在准确核对连接名和旧地址后删除该工作区连接并按新地址建回，其他工作区连接不动。底层 `chatgptRepair.needed` 与连接名/地址是操作依据；需要新配对码时用 pair。自动恢复两轮无进展就交接原因和最后证据；本地其他工作继续。维护完成后原窗口再次在自己的对话实际验证工作区与文件。

用户要求断开 ChatGPT 默认用 `unpair` 撤销当前工作区访问；明确要求停止组件才 `stop` 停止当前工作区桥和隧道。两者不可混淆。断开、重新启动和恢复的报告要说明实际执行项，不把模拟测试当实测。
